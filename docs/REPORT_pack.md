# Русская озвучка вшита в игру — FMOD 4.33 не понадобился

Дата: 2026-09-11. `bigfile_ENGLISH.000.tiger` пропатчен, резерв — `...tiger.bak`
(побайтно совпадал с оригиналом перед началом).

## Почему FSBank был не нужен

Задача формулировалась как «собрать FSB4», но игре не нужен новый банк. Заголовки
банка и сэмпла в архиве уже правильные — менять надо только звуковые байты.
А чтобы их подменить, нужно было разобрать раскладку, которая в прошлом отчёте
осталась «не доразобранной».

Инструмент, который всё решил, оказался в самой игре: `Game\fmodex.dll` —
это FMOD Ex 4.33.9. Его можно вызвать из 32-битного PowerShell (`oracle.ps1`)
и декодировать любой банк-кандидат **тем же кодом, что и игра**, не запуская игру.

## Формат звукового потока

Запись архива:

```
[обёртка ~9 КБ — субтитры на 8 языках]
[FSB4: 48 б заголовок банка + 80 б заголовок сэмпла]      имя NAME.str_0
[чанкованный поток — до конца записи, а не до dataSize]
```

Чанк: **16 байт заголовка** (`u32` размер полезной части, `u32` номер потока,
8 байт магии `CD CD CD CD CD CD CD CD`), затем полезная часть; всё выровнено
на 16 байт. Между чанками движок вставляет 32-байтные cue-записи (похоже, липсинк).

Полезная часть звукового чанка — MPEG-кадры, **каждый в своём 316-байтном слоте**,
хвост слота забит нулями. 316 — это максимальный кадр 96 кбит/с при 44,1 кГц (314),
выровненный на 4 байта; флаг банка `0x40` = `FSOUND_FSB_SOURCE_MPEG_PADDED4`.

Три факта, которые всё замыкают (проверены на **всех 983 записях, расхождений 0**):

| | |
|---|---|
| число кадров | ровно `lengthSamples / 1152` и `lengthCompressed / 316` |
| длина кадра | всегда ≤ 316, кадр стоит в начале слота |
| `main_data_begin` | **0 у каждого кадра** — бит-резервуар не используется |

Поток продолжается **за** границей `dataSize` до конца записи архива: у первой
разобранной реплики в `dataSize` влезало 105 кадров из 122, остальные 17 лежали
в «хвосте» записи. Раньше это выглядело как «кадры теряются».

Семь реплик — **стерео**: в них два потока, `NAME.str_0` и `NAME.str_1`, их чанки
чередуются, а первый чанк потока 1 начинается со своего же 128-байтного заголовка
FSB4. Номер потока и есть то самое поле «тип» в заголовке чанка.

## Что именно ломало прошлые попытки

`main_data_begin = 0` — не деталь, а жёсткое требование. LAME по умолчанию
пользуется **бит-резервуаром**: часть данных кадра переносится в свободное место
предыдущего. В нашем `vo96/` так и вышло — резервуар использовался в 121 кадре
из 122, со ссылками до 506 байт назад. В раскладке по слотам, где между кадрами
стоят нули и заголовки чанков, такой поток рассыпается: декодер читает мусор.

Лечится одним флагом: `ffmpeg -reservoir 0`. После него `main_data_begin = 0`
у каждого кадра, и кадры можно переставлять как угодно.

Вторая причина: `fsb4patch.py` писал банк от FSBank поверх записи целиком — вместе
с чанковыми заголовками и cue-записями, которые читает движок. Отсюда, судя по
всему, и четыре краш-дампа за сегодня.

## Доказательства (получены без запуска игры)

Родная `fmodex.dll` игры, `oracle.ps1`:

| банк | объявлено | декодировано |
|---|---|---|
| вырезанный из архива как есть | 140544 сэмплов | **52992** — FMOD не понимает чанки |
| он же, со снятой чанковкой | 140544 | **140544**, RMS 4857 — чистая речь |
| собранный FSBank'ом из `fsbankex` | 149760 | 149760 — формат сам по себе рабочий |
| **наш русский банк** | 140544 | **140544**, RMS 4497 |

Сверх этого: то, что FMOD выдаёт из нашего банка, совпадает с прямым декодом того
же MP3 через ffmpeg с точностью **0,02 % RMS** — раскладка по слотам ничего не портит.

Четыре проверки на то, чего предыдущая строчка поймать не может:

- **Порядок склейки верен.** Оригинал, склеенный нашей же моделью, декодируется
  в осмысленную английскую речь (`3_dechunked`). Неверный порядок кадров дал бы
  кашу из рваных слогов, а не связную фразу.
- **Разделение стерео верно.** У всех 7 стерео-реплик потоки 0 и 1, восстановленные
  независимо из чередующихся чанков, оказались **побайтно идентичны**
  (85 952 байт против 85 952 и т. д.), а их декоды — с одинаковым MD5. Это дубль
  моно, так что запись одного и того же русского в оба потока — то, что и было.
- **Адресация верна.** Выборка из 12 случайных реплик: огибающая, вынутая из слотов
  патченного архива, совпадает со своим синтезом с корреляцией **1,000**, а с чужими —
  не выше 0,65. Перепутанных записей нет. Регистр имён тоже проверен: 983 записи
  различимы без учёта регистра, все 977 wav сопоставлены точным совпадением имени.
- **Лимитер не душит.** Подгонка громкости по RMS загоняла пики глубоко в лимитер
  (до 2,35 — это 7,4 дБ срезки, почти всё Исида). Введён потолок `пик × усиление ≤ 1,8`:
  теперь максимум ровно 1,8 (≈5 дБ), медиана 1,16 (≈1,3 дБ). Цена — те реплики
  на 2 дБ тише английских.

## Конвейер

| файл | что делает |
|---|---|
| `mul.py` | разбор потока: чанки, слоты, оба стерео-потока |
| `dub.py` | синтез → тримминг → подгон громкости и темпа → MP3 без резервуара → слоты |
| `apply.py` | вшивание в архив; всегда от `.bak` |
| `audit.py` | проверка модели на всех записях |

```
python apply.py 150_cs_010_  # только по префиксу
python apply.py --restore    # вернуть оригинал
```

## Состояние

**Вшито 982 реплики из 983.** Английской осталась одна — `600_pu_010_530_lara`,
у неё в игре нет русского текста ни в одной карточке. Русской речи 45,7 мин
из 53,1 мин слотов. Проверено после патча:

- размер архива тот же — 55 628 240 байт;
- **вне отведённых слотов не изменён ни один байт**: заголовки чанков, cue-записи,
  заголовки банков, таблица TAFS, субтитры — как были;
- полный разбор патченного архива: 990 потоков, **расхождений 0**.

Громкость подогнана по каждой реплике: синтез оказался примерно в 2,7 раза тише
английской дорожки (медианное усиление 2,68), с потолком по пикам.


## Потерянный текст: 38 % реплик не было в озвучке

Главная ошибка первой сборки была не в звуке, а в извлечении текста. Субтитр
реплики — это **не один блок перед банком**, а несколько карточек, разбросанных
по всей записи между звуковыми чанками, с тегом вида `[b1c3d3.4]`, где `d` —
время показа карточки. Старый разборщик брал только первую.

Пример — `150_cs_105_040_carter`, 13,64 с звука:

```
[b1c3d3.4]  Э... Этот урок истории я дам тебе потом, Гор. Смотри,
[b1c3d5]    вот другие его имена: "Острозубый" и "Тот, кто ест".
[b1c3]      Эта фреска изображает его как бога Нила и воды.
```

Озвучивалась только первая строка. Порядок карточек — байтовый, он же порядок речи;
тег `d` не монотонен и порядком не является.

| | было | стало |
|---|---|---|
| русского текста | 30 010 знаков | **41 504** (+38 %) |
| реплик с несколькими карточками | — | 216 (до семи карточек) |
| реплик «без русского текста» | 6 | **1** (`600_pu_010_530_lara`) |

Пять из шести «немых» реплик текст имели — он просто лежал не в первой карточке.
Все 216 многокарточных плюс три найденные реплики Сета пересинтезированы через
fish.audio полным текстом (`regen.py`, прежние варианты сохранены в `vo_wav_1card/`).
Скорость синтеза задавалась самой моделью (до 1,25×) — это звучит лучше, чем
последующее `atempo`.

Заодно проверено: у односоставных реплик расхождений старого и нового текста **ноль**,
а всего банков FSB4 в архиве ровно 990 = 983 реплики + 7 вторых стереопотоков,
то есть пропущенного звука нет.

## Обрывы убраны полностью

Три изменения, каждое уменьшает нужное ускорение:

1. **Сжатие внутренних пауз** синтеза: паузы длиннее 180 мс режутся до 90 мс.
   На большинстве реплик даёт 0, на отдельных — до 34 %.
2. **Обрезка по относительному порогу** — 4 % от собственного пика вместо
   фиксированного. У коротких выкриков синтез оставляет полсекунды затухающего
   выдоха, которого фиксированный порог не ловил: у «Эй!» в слоте 0,39 с нужный
   темп упал с 2,49× до 1,38×. На обычных репликах срезает 0,06 с.
3. **Точный темп под каждую реплику** без общего потолка, цепочкой `atempo`
   (один фильтр не тянет больше 2×).

| темп | реплик |
|---|---|
| без ускорения | 628 |
| до 1,2× (не слышно) | 221 |
| 1,2–1,5× (слышно) | 105 |
| 1,5–1,8× (быстро) | 18 |
| 1,8–2,2× (на грани) | 6 |
| выше 2,2× (скороговорка) | 4 |
| **обрезано** | **0** |

## Что осталось

1. **94 реплики обрезаны** — русский не влез даже при ускорении 1,35×; суммарно
   потеряно 21,1 с, заметно (>0,4 с) в 12 репликах. Лечится сокращением текста
   и повторным синтезом; список — в `apply_report.json` по полю `cut`.
1a. **93 реплики звучат по-английски** — см. раздел выше. Уменьшить их число можно
   только вручную: слушать оригинал и класть русскую фразу туда, где в нём слова,
   а не в начало слота. Автоматически отличить слова от смеха я не берусь.
2. **6 реплик остались английскими** — для них нет русского текста ни в одном языке
   (`150_cs_010_080_set`, `150_cs_150_010_set`, `150_cs_150_020_set`,
   `150_cs_150_030_set`, `250_tm_120_370_set`, `600_pu_010_530_lara`).
3. **155 реплик на потолке усиления** (4×) и 166 с ощутимой работой лимитера
   (пик × усиление > 1,5) — останутся тише оригинала. Список вместе с обрезанными —
   `needs_rework.json`, 249 реплик; лечение у обеих групп одно: вернуться к синтезу.
4. **Ролики** `LC2Intro.bik` / `LC2Outro.bik` — по-прежнему английские, русские
   субтитры к ним есть.
5. **Липсинк** в кат-сценах анимирован под английский — это не исправить.
6. Проверка в самой игре — единственное, чего нет в этом отчёте.
